## Why

A live document has to be editable by the person too, while the agent keeps working, without closing anything or losing what was just typed. Edits go block by block, and a block the person has just changed must not be overwritten by an agent that has not read it.

## Acceptance criteria

- [ ] `PUT /api/docs/{id}/blocks/{block}` `{md, base_version}` replaces a block as `author: user`; `POST /api/docs/{id}/blocks` `{after, md}` inserts and `DELETE /api/docs/{id}/blocks/{block}` deletes. A `base_version` older than the block's current version returns 409 with the current block. A Go test of each route, of the 409, and that every open stream receives the change.
- [ ] The `doc` tool's `replace` and `delete` fail with an error that tells the agent to read the block again when the person changed that block after the agent last read or wrote it; edits to blocks the person has not touched still apply. A Go test: agent reads, user replaces block 2, agent replace of block 2 fails with that error, agent replace of block 3 succeeds, agent reads again and then replaces block 2.
- [ ] In the panel, clicking a block turns it into a text area with its markdown in place; leaving it or Ctrl+Enter saves, Esc cancels, Enter at the end of the last line inserts a new block below, and emptying a block and saving deletes it. On a 409 the panel shows the current text and a notice «L'agent ha canviat aquest bloc» / «The agent changed this block» and keeps the person's text to copy. A node test of the editing state machine (open, save, cancel, insert, delete, conflict).
- [ ] While the person edits a block, `block` events for that same block do not replace the text area; events for other blocks still apply. A node test.
- [ ] `docs/api-contract.md` documents the three routes and the 409.

## Out of scope

- Rich in-place formatting (WYSIWYG toolbar): blocks are formatted when shown and edited as markdown.
- The per-turn summary to the agent (060), Android (063).

## Notes

- The agent's last-seen version per block can live in the store, keyed by session, since 060 needs the same record.
- Block ids are generated by the server; the client never invents them.
