# Project and VS Code review — 2026-10-19

The Go backend already supports durable runs, permissions, checkpoints and
delegation. The VS Code client exposed only commands and a text OutputChannel,
which hid much of that functionality. The main product gap was the editor
experience and the reliability of the client integration.

The review used the official [VS Code view guidelines](https://code.visualstudio.com/api/ux-guidelines/views),
[Webview guidelines](https://code.visualstudio.com/api/ux-guidelines/webviews)
and [chat interaction documentation](https://code.visualstudio.com/docs/chat/chat-overview)
as reference. This is a feature comparison, not a claim of parity with all
capabilities or model quality of other coding assistants.

| Finding | Impact | Change |
|---|---|---|
| Commands plus plain text output were the only interface | Conversation, progress and next actions were hard to follow | Themed Activity Bar chat view, explicit context, modes, tool disclosures and subagent states |
| Concurrent commands could start overlapping runs | Cancellation could address the wrong work | One active turn, with matching undo exclusion |
| Configuration was re-read when answering approvals | A settings change could post a decision to another server/session | Capture routing and credentials for the whole run |
| Default sessions were shared between projects | Context from different projects could be mixed | Workspace-derived default session IDs and explicit workspace on submit |
| Legacy execution used the server workspace | Tools could run against a different project | Set the selected workspace before legacy execution; require success |
| HTTP/SSE decoding and incomplete streams were fragile | Unicode corruption, hangs and silent partial completion | Abort-aware bounded JSON requests, streaming UTF-8 decoding, CRLF framing and terminal-state checks |
| Final responses and lifecycle messages were conflated | Duplicate answers or replacement by a completion notice | Separate incremental tokens, final text, verification and run completion |
| Token was a plaintext setting | Credentials could be stored with ordinary configuration | SecretStorage command scoped to server URL; legacy setting deprecated |
| Long streams redrew and persisted on every token | Growing UI work during long tasks | Batched redraw, debounced persistence and bounded local history |

The sidebar deliberately follows VS Code theme tokens and accessibility
preferences. Editor actions, native decision pickers and Source Control remain
part of the normal editor workflow. No additional browser or rendering library
is needed in the extension.

## Validation

- Strict TypeScript checking, bundle compilation, VSIX packaging and 52 passing
  extension tests.
- Synthetic HTTP tests for lost acknowledgements, exact cancellation,
  independent sessions, legacy workspace routing, event pagination and failure.
- Webview behavior tests for streaming, final-response deduplication, tool
  identity, IME/keyboard handling and bounded transcript size.
- Native VS Code development-host activation: opens the view and submits the
  selected source in Inspect mode with the workspace-derived session.
- Playwright visual/interaction checks in light, dark and high-contrast themes,
  including 280 px width, keyboard submission, copy and stable disclosures.

The model/provider traffic in these checks uses synthetic fixtures. They test
the client integration, not the quality or speed of live-model answers.

The first full Go run also identified two fragile test fixtures outside the
extension. The TUI selection test enabled TrueColor before model initialization,
which then reapplied `NO_COLOR`; it now sets the test profile after initialization
without changing production color preferences. The parallel API test depended
on completing within 500 ms; a request barrier now proves that all three model
calls overlap and checks stable result ordering without a machine-speed threshold.
Both affected packages then passed their complete suites with
`go test ./internal/tui ./internal/web -count=1 -timeout=180s`. Every other
package passed in the initial full run. `go vet ./...`, release-metadata checks,
the source privacy scan and `git diff --check` also passed.

## Follow-up completed

The VS Code sidebar now lists backend-saved conversations, restores the
transcript and returns to the conversation's open project. Git diff selections
can be staged or discarded through explicit Gregal commands; discarding asks
for confirmation. Inline completions now use a separate short-lived, tool-free
backend request; diagnostic quick fixes can ask Gregal to fix or explain the
nearby code.

Follow-up validation: all 59 VS Code tests pass, TypeScript type checking and
the production bundle succeed, and VS Code packages the 0.6.0 VSIX. Conversation
restoration, inline requests, and diagnostic action routing are covered with a
synthetic backend; the Git commands are VS Code's built-in selected-range
operations.

The broader project has platform-specific release paths. The VSIX produced by
this change is a local review artifact; Marketplace publishing remains separate
from the desktop and Android releases.
