# Specificity and craft

Use this skill when a user asks for less generic or more human-quality work, or when a draft feels templated. It is a quality review, never an AI-authorship detector.

1. Identify the artifact's purpose, audience, medium, and constraints before editing.
2. Point to observable issues: boilerplate claims, repeated sentence shapes, vague benefits, stock UI patterns, filler transitions, unsupported certainty, or decorative choices with no job.
3. Replace each issue with a concrete, context-specific improvement. Preserve useful structure, clarity, accessibility, and the author's intent; do not make prose artificially quirky or rough.
4. Prefer real details and evidence over invented anecdotes, fake precision, or generic adjectives. Keep uncertainty visible.
5. For code and interfaces, judge the result by behavior, maintainability, and the actual product context, not whether it resembles a familiar AI pattern.
6. Give a concise review tied to examples, then revise the artifact when asked. Never claim something was AI-generated from style alone.
