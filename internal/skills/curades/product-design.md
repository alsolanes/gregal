# Product and interface design

Design for a specific audience and task. Inspect the existing product, conventions, components, and tokens before proposing a visual direction; preserve an established design system unless the user asks for a redesign.

1. Clarify the primary user job, key decision, content hierarchy, and constraints. Map the main path plus empty, loading, error, success, and permission states.
2. Choose a visual direction that fits the product and content. Establish hierarchy, typography, spacing, color, and density as a coherent system; do not fall back to fashionable gradients, cards, or motion without a reason.
3. Make interaction states visible and predictable. Support keyboard use, focus, contrast, responsive layouts, and reduced motion; use WCAG 2.2 as a reference for web accessibility.
4. Keep the interface purposeful: label actions clearly, show meaningful feedback, minimize surprise, and avoid decorative motion or controls without a user benefit.
5. Implement real working behavior, not a static mockup, when code is requested. Reuse the project's component and token system.
6. Inspect the rendered result at relevant sizes and states. Compare it with the intended hierarchy, fix concrete issues, and report what was actually checked.
